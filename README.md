# 剧荒救星

韩剧和轻松搞笑综艺推荐站，使用原生 JavaScript 和静态文件，无第三方运行依赖。

线上地址：[iyf.hackx64.eu.org](https://iyf.hackx64.eu.org/)。

## 本地开发和验证

需要 Node.js 22（见 `.node-version`）。

```sh
node --test
node scripts/build-site.mjs
python3 -m http.server 8765 --directory site --bind 127.0.0.1
```

打开 `http://127.0.0.1:8765/`。必须使用 HTTP，直接打开 `index.html` 无法请求推荐 JSON。

构建命令先校验数据，再生成 `site/`。输出仅含首页、404 页面、CSS、JS、公开推荐数据、Cloudflare 响应头和 robots 文件；不会发布抓取缓存、历史记录或脚本。三个构建入口共用输出保护，禁止覆盖源码、原始数据和 `.env` 配置（含 `.env.*`）；符号链接、硬链接和父目录别名也不能绕过保护。复用完整站点输出目录时，发现未知文件会中止构建。

## 数据更新

GitHub Actions 每天在北京时间 08:23、20:23 运行抓取、回归测试、校验和提交。整点是 GitHub 调度高峰，计划时间因此避开整点；定时任务仍可能因平台调度延迟，页面展示实际数据更新时间。数据源故障时沿用上一快照，保留已有评分、播放量、集数、简介来源和真实更新时间。发现日志覆盖首页和搜索首次观察到的韩剧、综艺，按类型、地区、标题和年份同日累积；最终未通过收录规则的观察仍会保留，后续空结果不会抹掉已有记录。关键词搜索再次返回已收录节目的同一来源 ID 时会为其续期；与已有卡片同名的旧版本不会每轮被重新“发现”，只有本年度更新的同名新版本才进入收录流程。

首页 API 返回 403、服务错误或无效内容时，自动在源站的 `api.yfsp.tv` 和 `api.iyf.tv` 之间切换，并优先复用本次运行已成功的域名。每页的双源请求共用 15 秒预算。首页仍不可用时，通过公开搜索接口刷新已有具体链接的节目，每类最多 30 部、并发 3、总预算 90 秒，按最近一次确认或尝试搜索的时间轮换目标（连载节目提前一天），未命中的节目不会长期占用名额；只有命中足够节目且韩剧、综艺分别达到覆盖门槛才更新快照时间。首页未观察到的其他电视剧继续保留。所有来源均失败或覆盖不足时保留旧更新时间，超过 7 天仍会被新鲜度校验拦截。

部分首页响应只更新明确返回的字段，推荐和其他电视剧均保留缺失字段的上一快照；显式 `0` 和 `false` 仍可更新旧值。同名节目匹配同时检查地区和季身份，同季的“第5季”“第 5 季”“5”等写法可复用已验证身份。离线重算在 AI 混分前移除黑名单综艺。季节目使用对应季的海报，豆瓣链接须具备独立条目和季证据，系列 Wikidata 链接不会覆盖已验证的季链接。外部元数据暂时失败与封面成功缓存分开处理，按限额和时间预算重试，避免外链永久缺失。

新内容的首次发现日期按节目身份保留，避免不同地区、类型或翻拍的同名节目串用日期。外部接口的畸形记录按行隔离，不影响后续有效结果；可选链接搜索和验证请求受阶段及全局剩余时间预算限制。搜索先验证候选链接，再排名；畸形响应无法确认不存在时只使用短暂的未知状态缓存。自由文字截断保留完整 Unicode 字符，损坏的来源标识按行拒绝。

TMDB 详情和简介核对请求主体及已知季身份，海报路径校验后才生成地址；错误响应不会覆盖可靠封面或建立“不存在”缓存。豆瓣和 Wikipedia 的超时返回也不会写入已有节目。

页面在更新失败时继续展示有效本地缓存，切换分类仍保留提示；首次加载失败可直接重试并保留筛选。网络数据与缓存都先校验实际渲染字段，校验或绘制失败的网络快照不会写入缓存；坏缓存或绘制异常仍可通过网络恢复。后台刷新按节目身份保留键盘焦点和阅读位置，节目移除或分页按钮隐藏时提供可达的焦点回退。清除筛选、加载重试和自动末批加载也会保留可达焦点；内容跳转按固定导航的真实高度留白，适应移动布局和字体变化。手动加载更多后，键盘焦点移到第一条新结果。

推荐 JSON 在 HTML 头部预加载，与脚本并行请求，并提前连接实际使用的 TMDB 图片源。首次推荐内容直接显示，卡片和数字的入场动画保留给后续分类切换。年份筛选按分类计算一次，卡片共用本批年份，避免逐条重复扫描整个数据集。结果与渲染上下文未变时保留原卡片和已解码海报；同内容的后台响应也沿用原快照。新快照、推荐度基准、年份或分类变化，以及骨架和错误状态，均会让卡片复用失效。

TVmaze 时间表按韩国当地日期缓存，跨午夜立即重新请求。请求部分失败、超时或包含畸形记录时保留有效节目并显示提示，仅缓存一分钟；完整结果缓存十五分钟。简介中的 HTML 实体转为文字后再安全渲染。

```sh
# 从来源重新抓取，可选密钥仅通过环境变量或 GitHub Actions secrets 配置
node scripts/scrape.mjs

# 无网络重算现有推荐分，保留原始数据更新时间
node scripts/scrape.mjs --recalculate-existing
```

`TMDB_TOKEN` 用于高清封面，`OPENROUTER_API_KEY` 用于可选 AI 评分；可用 `OPENROUTER_MODEL` 指定模型。默认的免费路由每次随机选择模型，抓取器会优先复用最近一次返回有效结果的 `:free` 模型（从不固定付费模型），失败时退回免费路由，并把该模型作为私有状态保存到下一轮，以节省每天约 50 次的免费请求额度。缺少可选密钥时保留规则推荐与有效缓存。AI 输入明确标记十分制来源评分，未评分为 `null`；输出使用百分制推荐分，并校验分数与推荐档位一致。旧版量纲不明确的缓存会失效，真实低分不会被自动放大。AI 生成文案仅补充缺失文案，保留可靠的短简介，不参与规则评分或节目收录判断；即使生成文案较长，后续取得的可信简介仍可替换它。可信简介被较长文案替换时仍保留本轮已确认的内容排除证据；已纠正的错误实体及未经验证的旧系列简介不会成为对应季的排除事实。

## 发布

生产工作流仅在 `main` 运行，避免手动选择其他分支后白跑抓取。GitHub Actions 在抓取、校验和提交成功后构建 `site/`，再通过独立任务发布 GitHub Pages 和 Cloudflare Pages。两者使用相同的 `scripts/build-site.mjs`，Cloudflare 验收请求取得的线上文件必须与该次已校验产物一致才算发布成功。

Cloudflare 项目地址：[iyf-5l7.pages.dev](https://iyf-5l7.pages.dev/)。

站点按自定义域名的根路径部署，404 页面也按根路径定位首页和样式。

| 设置 | 值 |
| --- | --- |
| 项目名称 | `iyf` |
| 仓库 | `txdywy/iyf` |
| 生产分支 | `main` |
| 构建命令 | `node --test && node scripts/build-site.mjs` |
| 输出目录 | `site` |
| Node.js | `22` |
| 自动 Git 构建 | 关闭，由 Actions 部署钩子触发 |

Cloudflare 保留 Git 来源以从 `main` 构建，关闭自动生产与预览构建，避免与 Actions 重复发布。在 Pages 项目中创建指向 `main` 的部署钩子，将其完整 URL 保存为当前仓库的 Actions Secret `CLOUDFLARE_DEPLOY_HOOK`；当前项目已配置。钩子 URL 属于凭据，不应写进仓库或日志。

Cloudflare 发布任务下载本次工作流的已校验产物，触发部署后以 10 分钟为轮询期限，先确认两个域名的首页均已切换到新版本，再核对正式域名与 Pages 域名的首页、CSS、JS、公开数据、robots 和真实 404 的内容摘要、文件类型（Content-Type），以及缓存和安全响应头。失败日志包含具体域名、文件和受控原因（HTTP 状态、摘要差异、缺失或无效响应头、连接错误），不输出钩子、响应正文或头值。任一域名不可访问、触发失败或线上仍是旧文件时任务失败；GitHub Pages 独立发布，继续作为备用。代码提交、定时抓取和手动运行均经过这条链路，数据机器人提交不会再递归触发抓取。

缓存验收解析实际指令，正确处理大小写、引号和转义；HTML/JSON 必须包含无参数的 `no-cache`。安全策略按浏览器的重复指令和多策略规则核验，避免把字符串片段误认为有效保护。

自定义域名已启用 Cloudflare 访问性能统计，Cloudflare 可能对浏览器的 HTML 响应自动注入带完整性校验的统计脚本；构建产物本身不包含该脚本。HTTP 头和 HTML 的安全策略仅允许这一脚本的固定路径及版本子路径，同源上报沿用现有 `connect-src`。部署验收校验的是其请求实际取得的内容，不代表浏览器收到的 HTML 一定未被 Cloudflare 转换。

正式域名 `iyf.hackx64.eu.org` 的 CNAME 指向 `iyf-5l7.pages.dev`。HTML 和 JSON 使用重新验证缓存，CSS/JS 实际文件名包含内容摘要，并使用一年有效期的 `immutable` 缓存；新代码通过新摘要地址更新（参见 [Pages 缓存建议](https://developers.cloudflare.com/pages/configuration/serving-pages/#caching-and-performance)）。Cloudflare 通过 `_headers` 额外设置安全响应头。详情见 [Cloudflare Pages 部署钩子文档](https://developers.cloudflare.com/pages/configuration/deploy-hooks/)。

交付策略改变而资源内容未变时，旧摘要地址可能仍命中带旧响应头的缓存。此时同步更新对应资源的交付版本注释，让完整文件字节生成新摘要地址；文件名仍须与内容哈希一致，并通过两个域名的实际响应验收。
