# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

剧荒救星 — Korean drama & Chinese variety show recommendation static site. Scrapes YFSP (爱壹帆), enriches with TMDB/Wikidata/Douban/Wikipedia metadata and applies multi-factor recommendation scoring. GitHub Pages publishes the validated build. Cloudflare Pages rebuilds from Git and its output is checked against that build.

No package.json or third-party runtime dependencies. The site is pure vanilla JS;
small dependency-free Node scripts validate and project the deployment payload.

Before editing workflows, deployment verification or scraper freshness rules, read the [production release contract](README.md#生产发布约定). Keep the existing main Deploy Hook and artifact verification together. Treat hosting and credential changes as an explicit migration.

## Commands

```bash
# Run scraper (Node.js 22; see .node-version)
node scripts/scrape.mjs

# Recalculate the published recommendation scores without network calls
node scripts/scrape.mjs --recalculate-existing

# AI scoring — runs automatically when an OpenRouter key is present
OPENROUTER_API_KEY=sk-or-xxx node scripts/scrape.mjs
# Optional explicit model override; the default is OpenRouter's dynamic free router
OPENROUTER_API_KEY=sk-or-xxx OPENROUTER_MODEL=openrouter/free node scripts/scrape.mjs

# Serve frontend locally (must use HTTP, not file://)
npx serve .
python3 -m http.server

# Full local quality gate
node --test
node scripts/validate-data.mjs

# Build the minimized public recommendation payload
node scripts/build-public-data.mjs --output /tmp/shows.json

# Build the complete validated deployment artifact for both hosts
node scripts/build-site.mjs
```

The test suite is dependency-free and uses Node's built-in test runner. `scripts/regression-tests.mjs` can also be run directly while debugging.

## Architecture

**Single-file scraper** (`scripts/scrape.mjs`): ES module, runs the entire pipeline in `main()`:

1. Primary source: the paginated YFSP catalog `/api/list/getconditionfilterdata` (`YFSP_CATALOG_QUERIES`: latest-upload Korean dramas ×2 pages and mainland/Korean variety ×1 page, 36 rows each; `ids` = sort,type,region,…, sort 0 = latest upload, regions 1 大陆 / 5 韩国). Taiwan/Hong Kong catalogs are not requested because their latest uploads are mostly old concerts and talk shows. Rows whose region/media type differ from the query discard that page. The catalog is healthy with ≥30 rows and ≥10 in each recommendation category, and then counts as a primary-healthy source (`sourceKind: 'catalog'`, may lower `stats.totalScraped`); the homepage stays as a supplement for other regions' dramas, and the title-search refresh below still runs whenever the homepage is unhealthy so cards absent from the catalog keep renewing. The homepage `/api/list/index` ignores pagination since 2026-10 (every page repeats ~5 rows per section and has no Korean dramas), so each `isn` loop stops after two consecutive pages whose new IDs are under 20% of the page; homepage health is measured against the pages actually attempted and only the homepage's own rows. Then scrape the YFSP homepage API (up to 30 pages; site domains `YFSP_SITE_DOMAINS` = kubb.tv → yfsp.tv → iyf.tv with `api.`/`rankv21.`/`www.`/`static.` subdomains and per-run preferred-host failover for both homepage and search; a search mirror that failed is not retried per keyword; if the first four pages fail on every host, the remaining pages are skipped). New play links use the domain that actually returned data this run (default yfsp.tv until one is confirmed); existing `www.<old domain>/play/<key>` links migrate to it only after an observed key on the new domain matches a previous card's key on another domain. kubb.tv play pages are client-rendered (every ID returns HTTP 200 with the site template title), so they are never page-verified: template titles are `unknown`, missing-link lookups accept the strict search match directly, and `invalid` lookups recorded against kubb.tv URLs are restored → `Map<mediaKey, show>`. If homepage coverage is unhealthy, refresh known YFSP titles through rankv21 search: up to 30 per recommendation category, concurrency three, 90 seconds total. Targets rotate oldest-first by the latest of `lastLiveAt`, `scrapedAt` and the private `sourceSearchCheckedAt` attempt time, so repeated misses cannot monopolize the slots and completed shows still renew during long homepage outages; ongoing shows receive a one-day lead. Freshness advances only with at least 30 observed items and 60% coverage in each category (minimum three); preserve other dramas whenever the homepage remains unhealthy. Private `sourceKind` and search counters distinguish this path from homepage success. A shared YFSP circuit breaker opens after six consecutive network-level failures (any HTTP response, even 403, resets it; local budget aborts do not count): later YFSP searches, verifications, refreshes, lookups and keyword stages are skipped quietly for the run without marking attempt times or negative caches, and the log names the underlying error code (e.g. `ECONNREFUSED`). Only a homepage-healthy run may lower `stats.totalScraped`; search-fallback runs keep the previous baseline. Ongoing-episode refresh later in the run skips titles whose `sourceSearchCheckedAt` is under six hours old.
2. Split into KDramas / Variety / Other, merge with hardcoded seed libraries (SEED_KDRAMAS, SEED_VARIETY); title aliases and last-published enrichment are used to keep accepted cards stable when YFSP IDs/pages change
3. Discover new shows via dynamic current-year keyword search. A keyword result carrying an existing card's exact source ID renews that card's `lastLiveAt` (title aliases are not proof); a different-ID result whose title exactly matches an existing card is ignored unless it is a newer current-year edition, so older same-title editions are not rediscovered and discarded every run. A discovered show whose source ID already belongs to a card with a different identity (for example another season) is skipped rather than replacing that card. Each keyword-search stage stops after three consecutive failures or 90 seconds. With `TMDB_TOKEN`, `discoverKDramasFromTMDB()` adds an independent discovery source: TMDB `discover/tv` (KR origin, Korean language, premiered in the last 120 days, popularity order, two pages, 60-second budget, animation/documentary/kids/news/reality/talk genres excluded). Up to 10 new rows with a Chinese (non-Hangul, non-season) name, a valid poster and popularity ≥10 become `tmdb_tv_<id>` candidates with a prefilled reusable cover cache entry and TMDB details for episode status; they pass through the same rejection cooldown, rule threshold (TMDB popularity counts) and AI gate. A row whose TMDB series ID or title identity matches an existing card only refreshes that card's `tmdbPopularity`, `tmdbRating` and placeholder/missing `publishTime`. `discoverVarietyFromTMDB()` shares the same implementation for brand-new CN/KR reality/talk series (genres 10764/10767 checked again client-side, so an entity cannot become both a drama and a variety show; popularity ≥3, at most 5 per run, `VarietyExclude` applied, light keyword or `tmdbRating` ≥7 required since variety has no AI gate). Variety observation and discovery share `VARIETY_REGIONS` (mainland, Korea, Taiwan, Hong Kong); homepage observations of Taiwan/Hong Kong shows refresh already-published cards, while new ones must pass the discovery thresholds
4. Enrich from TMDB/Wikidata/YFSP/Douban/Wikipedia, with bounded concurrency, tri-state link verification, negative caches and time budgets. YFSP verification/refresh/lookup, Douban and description enrichment skip `category: 'other_drama'` (unpublished). A YFSP title search with no completed query (pure transport failure) records only the private `yfspLookupAttemptAt` for rotation, never a `yfspLookupState`; unused verify/refresh slots (kubb.tv pages are never verified) move to missing-link lookups within the 45-request cap. Invalid lookups keep their original-domain `yfspLookupUrl` during domain migration so they cannot be restored as unverifiable kubb.tv links. TMDB discovery refreshes popularity/rating/premiere for ID- or title-matched cards without touching `tmdbStatsCheckedAt` (so the details/episode refresh stays due), never writes a zero popularity, and skips candidates in `discoveryRejections` before requesting details
5. Reconcile status fields and compute final rule scores only after trusted-source enrichment
6. AI scoring via `callModelsAPI()`: category-specific Korean-drama/variety prompts, batched 10/batch, versioned input-hash cache with staggered expiry
   - Uses OpenRouter's official `openrouter/free` dynamic route by default; `OPENROUTER_MODEL` can select an explicit model
   - Requests use strict JSON Schema and a shared eight-minute budget with a 60-second per-request deadline, sized for free-router latency
   - Each batch makes at most two requests (an invalid/empty answer or transient 429 is retried once, likely on another routed model) with a 4096-token output cap for reasoning models. A daily free-quota 429, an auth/credit rejection, or four consecutive failed batches stops all later AI calls for the run. The free router picks a random model per request, so with the default router the scraper pins the last concrete `:free` model that returned a valid batch (never a paid model), tries it first, falls back to the router when it fails (the pin's first 429 in a run keeps it and a router rescue does not replace it; a second 429 drops it as upstream-limited), and persists it as the private top-level `aiPreferredModel` in `data/shows.json` for the next run; an explicit `OPENROUTER_MODEL` disables pinning. The account's free tier allows about 50 requests per day, so request efficiency matters more than retries. Batches are ordered by rule rank and alternate between drama and variety; logs name the routed model and the failure class (HTTP status, empty content/finish_reason, upstream error, truncation) without response bodies
   - LLM IDs are constrained to the current batch and IDs, scores, booleans, reasons and descriptions are validated again before use
   - Inputs use `sourceRating10` (null when unrated), while outputs require `recommendationScore100` and a consistent `recommendationLevel`: strong ≥70, moderate ≥40 and <70, weak <40. Genuine low scores remain on the 0–100 scale; ambiguous old responses are rejected. Reasons (`r`) are capped at 60 characters in the schema and prompt (40 requested), which keeps reasoning models from truncating JSON. New-drama admission uses the detailed K-drama scoring profile plus admission rules, and an admitted show's score is stored as its current-version AI score, so it is not scored again. Admission review runs in batches of 5 (`AI_DISCOVERY_BATCH_SIZE`) because reasoning models often spend the whole output cap thinking on 10. New drama admission requires both `ok=true` and a score of at least 40; when the AI gives no answer (no provider, quota or invalid output), only TMDB-discovered candidates with `tmdbRating` ≥7.5 (≥20 votes) and `tmdbPopularity` ≥20 that pass the hard content exclusion are admitted by rule, marked with the private `admissionSource: 'tmdb_rules'`; an explicit AI rejection is never overridden by those rules, and other unanswered candidates are deferred rather than admitted. The admission prompt states that a missing rating on a newly aired drama is not a reason to reject, and passes `trendingPopularity` (TMDB popularity) and `premiere`. A TMDB candidate with popularity ≥50 that the AI rejects but that passes the hard content exclusion is still published (`admissionSource: 'tmdb_hot'`) with the AI's low score, so it ranks lower instead of disappearing. Explicit rule or AI rejections are stored in the private top-level `discoveryRejections` (keyed by discovery identity, with `version` = `DISCOVERY_REJECTION_VERSION` and the AI reason as `detail`; bumping the version re-reviews older rejections) and skip enrichment and AI review for 3 days (rules) or 10 days (AI); missing AI answers are not rejections. AI display copy is generated only for published categories, not `otherDramas`
   - Generated descriptions are labeled in the UI and excluded from scoring facts; reliable short source descriptions are preserved. Prompt/cache version 4 invalidates the earlier ambiguous scoring contract
7. Record the private top-level `aiRunStatus` (`stopReason`: '' | quota | auth | credit | failures | budget; `requested` HTTP calls; `scored` valid batches) and `sourceCatalogPages`. Normalize output fields/URL hosts, drop non-renderable shows, and run continuity + schema guards before the atomic write. Continuity anomalies in the unpublished `otherDramas` are reported as Actions warnings and never block publishing the recommendation categories, which keep hard guards

**Frontend** (`js/app.js`): IIFE, conditionally fetches `data/shows.json`, renders the card grid and the optional live TVmaze schedule tab. The primary data request and remote-tab requests are bounded, abortable, versioned against stale responses and cached where appropriate. Current-year tab labels follow the dataset year, old tab aliases remain bookmark-compatible, and progressive rendering appends only newly requested cards. External links and numeric fields are validated before rendering.

Recommendation tabs use a compact poster grid (`.show-grid.is-compact`: 3 columns ≤480px, 4 columns ≤768px, `auto-fill minmax(170px, 1fr)` above; `POSTER_SIZES_COMPACT` must match). A card (`renderCard`) holds only the poster, up to two poster badges (AI ≥70, one new/classic marker), a "可播放" tag, the mark pill, the title, score and status; the title is an `<a class="card-open" href="?show=<id>#tab">` stretched over the whole card. Clicking it opens the detail sheet — a native `<dialog id="detailDialog">` filled by `renderDetail()` (full badges, tags, status and play count, cast, untruncated description, AI reason, source links, and a fixed bar with the primary action, 想看/看过 and 分享); modifier/middle clicks follow the link instead. Opening pushes a history entry with `show=<id>`, so Back, Esc, the close button and the backdrop all close it and the URL is shareable; `syncDetailFromUrl()` opens it from a deep link after data loads, and a URL change that only touches `show=` never re-runs filters. `getDetailShareUrl()` drops the sharer's filters. The schedule tab keeps full cards (`POSTER_SIZES_FULL`). The paragraphs below describe the same facts; link, badge, description and mark details now render in the detail sheet rather than on the card.

Shows with a safe `yfspUrl` get the "去观看" primary action; others get a secondary-styled "暂无播放源 · 查看资料" action to `primaryUrl`. The "只看可播放" checkbox persists as `playable=1` (absent means off, so old bookmarks keep working), and every sort puts playable cards first among equal keys. TMDB/豆瓣/Wiki/IMDb links form one compact row of ≥24px text links; status and play count share one line. Play counts are hidden for shows never live-observed (no `scrapedAt`/`lastLiveAt`) and labelled "历史播放" when the newest observation is over 14 days older than the snapshot's `generatedAt`. Variety status codes are formatted by `formatVarietyStatus()` (dates, 期 numbers, weekdays; other strings unchanged). A card has at most one new marker ("新加入" from `isNew`, otherwise year-based "新剧/新综艺", suppressed in the year and recent-arrival tabs); AI scores appear only at ≥70 as a labelled "AI 推荐" badge with a visible legend. Cards are `aria-labelledby` their `h3`, external links carry SR-only "：title（新窗口）" text and decorative emoji are `aria-hidden`. Filter-caused empty results offer "清除筛选" (shared reset logic, focus to search); the mobile filter toggle shows the active control count; the TVmaze tab hides "最多播放", "已完结" and the playable filter. Desktop grid is `minmax(220px, 1fr)` in a 1240px container (3/4/5 columns), and poster `sizes` must match those breakpoints. `index.html` ships the same six skeleton cards that `renderSkeletons()` writes; while the grid is `aria-busy` the spinner is visually hidden (SR text stays), and narrow screens reserve two lines for `#updateInfo` and the year tab labels' width, keeping mobile CLS near zero. An unchanged background response rewrites the local cache only when it is over a day old. A user-initiated tab change pushes a history entry so the back gesture returns to the previous tab; filters, sorting and search only replace the current entry. The ongoing/complete/high-score statistics are toggle buttons (`data-stat-filter`, `aria-pressed`) that set the status or ≥8 score filter; narrow screens lay the statistics out in one row. A fixed "回到顶部" button appears after 1.5 viewports of scrolling and hands focus to the active tab before it hides.

The detail sheet has "想看 / 看过" toggle buttons (`.card-mark`, `aria-pressed`); the card shows the current mark as `.card-mark-pill`. Marks live only in this browser under `localStorage` key `iyf:marks:v1` (`{ kind: 'iyf-marks', want, seen, hideSeen }`, keyed by `title|year` so source-ID changes keep them; a show has at most one mark; malformed storage starts empty). A click updates the sheet and the matching card (`data-mark-key`) in place without re-sorting; on the next filter/sort/tab pass watched shows sink to the end of their group and get `.is-seen`. The "我的片单" tab (`mine`) lists marked shows. Search covers all Korean dramas and variety from any recommendation tab: current-tab matches first, then matches from other categories with a `.meta-tag.category` label and "含其他分类 N 个" in the summary (the schedule tab still searches only itself). `#quickFilters` is a row of toggle chips rendered by `updateQuickFilters()`: 可播放 / 连载中 / 8 分以上 mirror the existing controls, "隐藏看过" appears once something is marked watched, and genre chips come from the current tab's `contentType` (≥3 shows and at most half the tab, top six). The single-select genre persists as `genre=` in the URL (validated by `normalizeGenre()`), and "清除筛选" also clears genre and hide-watched. The grid has one delegated click listener (`bindCardActions`) that opens the detail sheet; `bindDetail` handles clicks inside the dialog.

Recommendation responses and local caches share validation for every consumed render field, including optional dates, text, numbers, flags, aliases and statistics. Preserve legal missing/null fields. Cache rendering failures must still reach the network recovery path; persist a new network snapshot only after validation and completion of any required recommendation rendering.

The HTML preloads the same recommendation fetch with anonymous CORS and preconnects to the used TMDB image origin. Initial recommendation cards and statistics appear immediately; entrance/counting animations remain available for later tab changes. Year selection runs once per category/filter pass or rendered batch, never once per show. Treat loaded data as immutable snapshots: equal background responses keep the prior snapshot object, and identical visible object prefixes can retain card DOM. Card reuse is invalidated by dataset identity, tab, computed year, recommendation maximum or a changed visible prefix; skeleton/error writes explicitly reset render tracking. Hashed CSS/JS use one-year immutable caching, while HTML/JSON continue revalidation. Deployment verification requires the immutable CSS/JS policy as well as HTML/JSON revalidation.

Delivery-policy changes must also migrate an unchanged asset's URL when old response headers remain cached. Update that asset's delivery-version comment so its full-byte content hash changes, then verify both public domains. Do not relax the cache/header gate or replace the content hash with an unrelated version string.

When a changed background snapshot rebuilds cached cards, retain the focused programme/link and reading offset by programme ID. Make a retained card visible even if it moves beyond the current batch; provide a reachable card/main-content fallback when a programme, link or focused pagination button disappears. Explicit tab/filter actions retain their usual focus behavior.

Before hiding a focused action, move its focus to a reachable continuation: clearing filters returns to search, recommendation/TVmaze retries retain main-content focus, and automatic final-batch loading focuses the first appended card only when the focused pagination button disappears. Measure the sticky tabs into `--tabs-scroll-offset` at initialization and via ResizeObserver (resize fallback), with root scroll padding protecting content jumps and focus rings. Badge/button colors must remain readable over bright and dark posters, including hover states.

TVmaze works independently of the recommendation JSON, defaults to date/time ordering, and labels Korean-local airtimes. Cache reuse requires the same Korea-local date as the request, including empty and partial results. A failed current-day request with empty historical results retains the error/retry state or the previous schedule rather than caching an unconfirmed empty day. HTTP/JSON failures and timeouts during historical backfill preserve completed results, label the partial schedule, and cache it for only one minute; leaving the tab still cancels all writes from that request. Summary entities are decoded before final text escaping. Before the initial recommendation response arrives, filtering preserves the loading state. Ongoing filters/statistics require an explicit running status rather than treating unknown/upcoming shows as running. Progressive loading has both automatic observation and a keyboard-accessible button; manual loading focuses the first appended card while automatic loading preserves focus. Recommendation cache notices persist across local tabs, and an initial failure retries in place without losing filters. TVmaze validates consumed row fields before caching and rendering; malformed rows produce a brief partial cache rather than hiding valid programmes. The public payload retains first-seen timestamps, update messages and description provenance; regression tests exercise the actual public builder to catch projection omissions.

**Deployment** (`.github/workflows/scrape-and-deploy.yml`): Scrapes 2x/day (00:23/12:23 UTC; off the hour because top-of-hour schedules were delayed 3–6 hours) and on manual dispatch. GitHub still delays or drops those schedules by 2.5–9 hours, so a compensation pair runs at 04:47/16:47 UTC; for schedule events only, the `Decide scrape mode` step reads the committed `generatedAt` and, when it is under 8 hours old, skips scraping and behaves exactly like a push run (build/deploy committed data, no `IYF_REQUIRE_FRESH_DATA`) with a notice. Scrape mode is the `steps.mode.outputs.scrape` step output (also exported as the job output `scrape`), not a job-level env expression. Before scraping, missing `TMDB_TOKEN`, `OPENROUTER_API_KEY` or `CLOUDFLARE_DEPLOY_HOOK` secrets produce warnings only, never their values. The token-holding commit step retries `fetch` three times and runs git with `core.hooksPath=/dev/null`; `data/history.json` is tracked normally (not ignored). Workflows run `node --test --test-reporter=dot` (failures still print details). Pushes to main skip the scraper and build/deploy committed data, so code merges never spend the daily free AI quota; bot data commits use `github.token` and do not trigger runs, so `data/**` is not path-ignored and human data-only commits still deploy. The job validates and commits data changes (checkout keeps no credentials; the write token is supplied only to the commit step's git commands), builds the validated `site/` artifact via `scripts/build-site.mjs`, then publishes GitHub Pages and Cloudflare Pages in independent least-privilege jobs. The GitHub backup is `https://txdywy.github.io/iyf/index.html` with no custom-domain binding; the explicit filename avoids a cached redirect on the old directory URL. Restoring the formal domain on GitHub requires rebinding it, changing DNS and provisioning HTTPS. Its artifact is an exact copy of the Cloudflare artifact except for `/iyf/`-prefixed 404 stylesheet/home links, produced by `scripts/prepare-github-pages.mjs`. `scripts/verify-github-pages.mjs` rejects redirects and checks six public file hashes, MIME types, and the nested 404 status (seven checked routes in total; on deadline it reports the last real differences) and content against the deployed backup artifact, with a 5-minute deadline. Cloudflare retains the Git source but has automatic production/preview builds disabled. The Cloudflare job downloads its own artifact and calls `scripts/deploy-cloudflare.mjs` with the deploy hook for main. Pages rebuilds with `node --test && node scripts/build-site.mjs`; the job waits for both homepages to match before requesting assets, then verifies all six public file hashes, the actual 404 status, and cache/security headers on both the custom and Pages domains against the validated artifact. Polling has a 10-minute deadline; individual network requests also have timeouts. Controlled diagnostics identify each failing domain/file, HTTP status, hash prefix, header name or allowlisted transport error; hook credentials, response bodies, header values and raw exceptions are never logged. A Cloudflare failure does not prevent the GitHub Pages backup from publishing. If `main` advances during a run (with or without data changes), the job emits a notice and skips publishing; the push run for the newer commit deploys it with committed data, and the next scheduled scrape refreshes data; the Cloudflare job also checks `origin/main` against `ARTIFACT_SHA` immediately before requesting the build. If polling times out with only content hash differences and `main` has advanced, the artifact is reported as superseded. Hook, HTTP, transport and response header failures still fail the job. Only scraping runs set `IYF_REQUIRE_FRESH_DATA=1`, which requires the scraper to have refreshed `generatedAt` within a day. An old `lastUpdated` (kept from the last healthy snapshot while the source is degraded) never blocks publishing; a non-healthy `sourceStatus` and recommendation data older than 48 hours or seven days are surfaced as Actions warnings. After both deploy jobs, a `health` job (`if: always()`, only scraping runs on main) checks out the published sha (or `main`) and runs `scripts/check-health.mjs`, which writes a step summary and fails the run (without affecting the already-finished publish) when a non-healthy source has a `lastUpdated` older than 48 hours or the private `aiRunStatus.stopReason` is `auth`/`credit`; `search` source fallback (anything other than `homepage`/`catalog`) and `quota`/`failures`/`budget` AI stops only warn, and a missing `aiRunStatus` is tolerated. `validate-data.mjs` type-checks the optional private `aiRunStatus`, enforces committed-data content rules (retired cards such as `黑暗荣耀第2季`, public category statistics) so tests never depend on committed data, and the public payload never projects `aiRunStatus`/`sourceKind`. `deploy-cloudflare.mjs` retries `git ls-remote` for `origin/main` three times with a 2-second backoff and still fails if every attempt fails.

The shared builder validates render-field types, projects only public fields, emits CSS/JS with content hashes in their filenames, includes a real 404 and Cloudflare cache/security headers, and rejects unexpected files, symlinks and hard links in output. Protected source directories are checked through parent aliases and filesystem identities before any writes. `.github/workflows/validate.yml` runs the read-only quality gate on pull requests. Action references are pinned to immutable SHAs and updated by Dependabot.

All three build CLIs use `scripts/build-output-path.mjs` for strict argument parsing and output protection. Source files/directories and `.env` variants cannot be overwritten directly or through aliases/inodes; normal `site/` and temporary outputs are allowed. Deployment verification requests are limited by the remaining polling budget and cannot report success after its deadline. The production scrape job runs only for `refs/heads/main`; non-main manual dispatches skip it before making external requests.

Deployment verification also checks each file's Content-Type essence, accepting optional charset parameters and both standard JavaScript types. Correct bytes served with an unusable MIME type must fail verification, especially with `nosniff`; diagnostics expose the header name only.

Parse Cache-Control directives with quoted values and escapes, rather than substring matching. HTML/JSON require unqualified `no-cache`; quoted extension values cannot establish revalidation or immutable asset policy. CSP checks follow the first occurrence of each directive within a policy and the combined restrictions of multiple policies.

Cloudflare Web Analytics is enabled on the custom domain and may inject its SRI-protected beacon into browser HTML responses. Both the HTTP and meta CSP must allow only `https://static.cloudflareinsights.com/beacon.min.js` and its version subpaths; automatic analytics reports to the existing same-origin `connect-src`. The deployment verifier compares the bytes returned to its own requests, which does not guarantee browser HTML is untransformed by Cloudflare. Keep other third-party script paths disallowed.

GitHub Actions secrets: `OPENROUTER_API_KEY` (AI scoring), `TMDB_TOKEN` (TMDB API v4 Read Access Token for high-res poster images), and `CLOUDFLARE_DEPLOY_HOOK` (the full Pages deploy hook URL for main). `OPENROUTER_MODEL` is an optional Actions variable; when unset the scraper uses `openrouter/free`.

## Key Data Flow

Show object fields include `id`, `title`, `titleAliases`, `year`, `score`, `playCount`, `publishTime`, `actor`, `description`, `mediaType`, `regional`, `category`, `recommendScore`, `coverImg`, `primaryUrl`, enrichment URLs, YFSP hotness metadata and versioned AI cache metadata. The deployed JSON contains only fields consumed by the frontend and omits `otherDramas`; `scripts/build-public-data.mjs` also drops null, empty-string, empty-array and `false` flag values (missing is equivalent in the frontend), except `firstSeenAt`, `scrapedAt`, `updateMsg` and `descriptionSource`, which are published verbatim. Descriptions are never truncated.

Link priority: `tmdbUrl > doubanUrl > wikipediaUrl > imdbUrl > yfspUrl` → `primaryUrl`.

A seed with no live match in the current run keeps the source ID and title its card published last run (unless another card holds that ID), so card IDs do not flip between seed and source IDs as the search rotation changes. A YFSP synopsis of at most 80 characters does not replace a longer TMDB/Wikipedia synopsis stored by the previous run (season cards keep a season-verified TMDB synopsis), which stops the same synopses being refetched every run; hard-exclusion evidence in the YFSP text is still remembered. Seed fallback must preserve previously observed dynamic facts and source descriptions when upstream fields are absent; explicit source values such as `0` and `false` still replace old values. Known erroneous legacy seed metadata is migrated before merging or recalculation so the old snapshot cannot restore that error. Positive YFSP page verification refreshes `lastLiveAt`, while failed or inconclusive checks do not. Same-day discovery history accumulates by title/year identity across runs. Discovery must not promote an existing media ID again under a title alias or an older premiere year. Season-specific aliases (for example `酒鬼都市女人们第1季`) are compared by season before edit distance, so an unnumbered seed cannot absorb a differently numbered `第N季` live season. First-seen dates use the same identity checks as source matching, reject invalid/future timestamps and preserve the original date across source ID changes. Optional YFSP searches and verification fit both stage and global remaining budgets and reject late success. Structured numeric input and malformed discovery/metadata rows must not interrupt later valid observations.

The same partial-field merge applies to live `otherDramas` observations. Seed/live and title-based snapshot matching require compatible regions. Offline recalculation drops negative rule scores before applying AI adjustments, so excluded variety cannot reappear through a high AI score. Discovery monitoring compares homepage observations against identities known before the run, rather than the already-populated recommendation maps. Drama and variety logs share same-day accumulation by media type, region, title and year; legacy untyped drama records remain compatible, and final admission rejection does not erase an observation.

Trusted description upgrades preserve any hard content exclusion already established during the current run, using non-enumerable derived state before final admission. Retiring an unverified whole-series synopsis does not establish season facts; wrong-entity cleanup occurs before description enrichment. AI display copy remains excluded from source evidence. YFSP search validates usable candidate URLs before ranking, and malformed-only responses remain `unknown` rather than establishing a long negative cache. Free-text limits preserve complete Unicode characters; malformed or overlong source identifiers are rejected per row rather than repaired into a different identity.

Completed Douban misses (`doubanMissCheckedAt`/`doubanMissTitle`) and TMDB synopsis lookups that found nothing better (`descriptionTmdbCheckedAt`/`descriptionTmdbCheckedPath`) are not repeated for 7 days unless the title or TMDB path changes; failed requests never record a miss. Chinese Wikipedia summaries are requested with `Accept-Language: zh-cn`; the private `descriptionWikipediaVariant` records the returned `Content-Language`, so legacy Traditional descriptions are refetched once rather than every run. Long AI display copy must not suppress later TMDB/Wikipedia source prose, even when the reliable synopsis is shorter. External metadata has an independent state/timestamp from the positive cover cache: unknown results retry after 18 hours and complete results after 30 days. Refresh only reusable entities in the current run, grouped by media kind and TMDB ID; cap at six entities, concurrency three and 40 seconds within the global enrichment deadline. Migrate old entries gradually in oldest-first order; retain independently verified season subjects and reliable existing links, and reject malformed or late results. These cache fields stay private; public projection also omits the unused `coverSource` field.

Season-specific TMDB covers require observed series identity and the matching season number. A title copied from the input or a previously published URL is insufficient evidence for an unverified series. Rejected identities must remain rejected across negative-cache retries; confirmed mismatches clear associated cached external links and sourced descriptions as well as the TMDB link and poster. Independently verified metadata and transient failures preserve reliable media. Season descriptions use the matching season endpoint and never substitute the whole-series Wikipedia description. Legacy series descriptions are rechecked even when long, and a confirmed season synopsis can replace a longer series synopsis. `descriptionTmdbSeasonUrl` records that verification in the private source snapshot so a confirmed short synopsis survives merging without repeated requests; the public projection omits this bookkeeping.

TMDB direct details and synopses must match the requested entity ID (and the known season ID/number). Direct mappings can require a particular year, region and media type; newly recorded cover caches retain a known region and cannot be reused for a different or unknown region. Validate relative poster paths from details, image lists and search results before building URLs; malformed optional responses preserve verified content and cannot establish negative caches. When both cached TMDB ID and entity URL exist, they must agree and the URL must have the appropriate TV/movie kind. Douban and Wikipedia responses received or decoded after the enrichment deadline must be discarded.

Persist the TMDB name that actually matched, including explicit English search mappings, so a successful poster stays reusable. For non-season Korean dramas with an independently verified Douban subject, an exact subject/title/year match may supply a Hangul original title after ordinary TMDB search fails. Accept only a unique TMDB result with the same original title, Korean origin, matching first-air year and one result page; persist the identity evidence with the cover and revalidate it on reuse. A new verified Douban identity bypasses an older negative cache once, while completed misses record the checked subject and use the normal retry interval; malformed, late or failed requests never create a negative result.

A missing series poster does not disqualify a matching season poster. Series-level Wikidata Douban links do not establish a season subject; cover enrichment and cache reuse prefer independently verified URL/subject ID/title/season evidence, and discard mismatched evidence together. `doubanMatchedSeasonNumber` preserves season evidence present only in a suggestion's English subtitle; it remains private along with the other matching metadata. Series Wiki/IMDb links remain available.

## Recommendation Scoring

`scoreKDrama()`: Genre boost (comedy +25, romance +20, horror is hard-excluded instead — keywords always count in the title and genre tags, while in the free-text synopsis fixed figurative/political phrases such as 恐怖传说 or 恐怖分子 (`KDRAMA_BENIGN_DESCRIPTION_PHRASES`) are ignored; military/cooking/growth subtopics also receive positive weight) + negative content penalty (-40/keyword) + quality score + YFSP hotness + freshness bonus + high-quality bonus (score ≥8.5 since 2015) + completion bonus. Keyword tables avoid entries that are substrings of another entry, so one theme is not counted twice.

`effectiveRating()` prefers the YFSP `score` and falls back to the public `tmdbRating` (only stored with at least 20 TMDB votes) for K-drama scoring, discovery thresholds and AI input; the UI labels it as a TMDB rating and uses it for score filters, sorting and statistics. Without YFSP plays, or when the last YFSP observation (`lastLiveAt`/`scrapedAt`) is 14+ days old so the play count is frozen, K-drama hotness uses a 75%-weighted logarithmic `tmdbPopularity` score. `refreshKDramaTMDBStats()` refreshes `tmdbPopularity`/`tmdbRating` for existing K-drama cards with a TMDB series ID (seeds included), oldest `tmdbStatsCheckedAt` first: 20 per run, concurrency four, 45 seconds, 3-day TTL; only ID-matching responses are written; ongoing cards refresh daily. `refreshTMDBStats()` serves both K-dramas and variety, and for single-season, non-season-titled cards without a recent YFSP observation (TMDB-discovered cards never count as YFSP-observed) it also updates episode status and completion from TMDB details. Variety uses `effectiveRating()` and an unrated current-year prior of 21, but keeps YFSP hotness for cards with play counts (many season cards lack TMDB series IDs); TMDB popularity applies only to variety without plays. `kdramaAiringBonus()` adds +8 for ongoing dramas and +15/+8 for exact premieres within 30/90 days (year placeholders and upcoming premieres excluded). Unrated current-year K-dramas get a neutral quality prior of 34 (60% of a 7.0 rating, no low-score penalty) instead of zero.

`scoreVariety()`: Similar, using the same YFSP hotness metric, with `VarietyExclude` blacklist (returns -1 to exclude entirely).

YFSP hotness is capped at 20 points: cumulative play volume contributes 0–8 logarithmic points, while average plays per day since `publishTime` contributes 0–12. A search `publishTime` of `YYYY-01-01T00:00:00` is a year placeholder and is treated like a year-only date. If only `year` is available, the inferred release date is marked as `year` and the velocity component is discounted to 45%; this keeps old seed cards usable without treating an estimated date as exact. Live/search matches replace stale seed play counts and publish times before scoring.

AI blending is category-aware: variety receives a mild adjustment, while Korean dramas use ×0.4 above 50 and ×0.8 below 50, so the adjustment is continuous and monotonic. Final variety rescoring drops excluded (-1) shows before AI adjustment, matching offline recalculation. Variety host bonuses read only `actor`. Only an AI score matching the current prompt version and stable input hash participates.

## Title Matching

`normalizeTitle()` strips punctuation and a trailing year while preserving season markers. `TITLE_ALIAS_MAP` maps known variants into symmetric groups. Matching uses exact/alias identity and conservative edit distance for longer names; substring matching is intentionally excluded to avoid merging specials or similarly named programs. When both titles have an explicit season, compare normalized season numbers and base titles so equivalent suffix spellings match while different seasons remain distinct. Cache reuse also checks this stricter identity when live/seed IDs change.
